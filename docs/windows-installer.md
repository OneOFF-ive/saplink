# SapLink Windows 安装指南

本指南面向使用安装包的用户，不需要下载源码或安装开发工具。安装包、快捷方式统一使用 SapLink 名称；配置与安装标识见 [命名与本地数据](local-data.md)。

## 安装前准备

- x64 电脑运行 Windows 10（1809 或更新）或 Windows 11；ARM64 完整包需要 Windows 11。
- 优先通过 [官网入口](https://saplink.cloud/download.html)读取 COS 版本信息并直接从 COS 获取所需版本；COS 不可用时使用 [GitHub Releases](https://github.com/OneOFF-ive/saplink/releases)。官网不保存安装包。选择架构时：Intel / AMD 电脑选择文件名包含 `win-x64` 的 `.exe`；Windows ARM64 电脑选择包含 `win-arm64` 的 `.exe`。
- RFC 连接准备应用服务器、两位系统号、三位 Client、用户名、语言，以及需要时的 SAProuter 路由；HTTP 连接准备 ADT 地址。密码稍后在本机输入。

内部完整包包含 Node.js、Java 和 JCo，无需另装这些组件或设置环境变量。Windows ARM64 完整包需要 Windows 11，RFC 使用独立 x64 Java/JCo 子进程。安装过程无需联网，连接 SAP 时需要相应网络。管理页面需要可用的默认浏览器。

命令行入口为 `saplink`。安装完成后重新打开终端，确保新的 PATH 生效。

## 安装应用

1. 双击与你电脑匹配的安装包。
2. 按向导选择安装位置，建议保留“加入 PATH”和“桌面快捷方式”选项。
3. 完成安装。应用仅安装给当前 Windows 用户。
4. 双击桌面的 **SapLink**，或开始菜单中的 **SapLink 管理界面**。

当前版本尚未进行发布者代码签名，Windows 可能显示“未知发布者”或 SmartScreen 提示。先确认安装包来自可信来源；不能确认来源时不要继续安装。

## 首次使用

打开后，任务栏右下角出现托盘图标。包含 SAP 助手的版本默认进入「工作空间」，可从顶部切换到「连接配置」。

1. 添加 SAP 连接，在本机输入登录信息。
2. 测试连接，确认可以访问 SAP。
3. 将完整的 [saplink-manager 技能目录](../skills/saplink-manager/SKILL.md)导入支持本机命令的 AI 客户端。
4. 用自然语言提出任务，由技能通过 CLI 使用已保存的 SAP 连接，见 [CLI 指南](cli-client-guide.md)。

包含 SAP 助手的版本也可直接从顶部进入「工作空间」，在「模型设置」保存 DeepSeek API Key。MCP 服务和访问令牌可按[运维手册](operations.md)配置，用于第三方客户端接入。

默认先保持写入关闭，可以先进行读取和查询。需要开发变更时，再为目标连接启用写入。

关闭浏览器标签页不会退出应用。再次点击快捷方式或双击托盘图标可重新打开页面；通过托盘菜单 **退出 SapLink 管理** 或 `saplink app stop --json` 正常退出，已启用的 MCP 也会关闭。仅停止 MCP 可用 `saplink mcp stop --json`，管理页面保持可用。

## 升级与修复

应用和服务启动后查询最新正式版，运行期间每小时再检查。有新版本时，顶部「系统设置」显示红色 **New**，旧版本的入口名为「软件更新」。进入更新区域可查看版本并选择「立即自动更新」，也可以手动点击「检查版本更新」。确认自动更新后，程序会下载并校验安装包，正常关闭当前应用，在原目录安装并尝试恢复原运行状态。

可执行 `saplink update check` 手动检查，CLI 普通检查缓存 24 小时；使用 `saplink update check --force` 立即重新查询。检查不停止应用、不下载或安装文件；设置 `SAPLINK_AUTO_UPDATE_CHECK=0` 并重启可关闭自动检查。

检查需要联网访问 COS 或 GitHub，不影响离线安装和已有 SAP 服务。没有公开正式版或网络检查失败时不能判断已是最新版。旧版本不支持该命令时，直接查看 [GitHub Releases](https://github.com/OneOFF-ive/saplink/releases)，按本机架构选择安装包。

以下步骤用于手动升级或修复；在管理页选择自动更新时，由更新程序处理正常退出和安装。

1. 先通过托盘菜单退出应用；如果使用命令行启动服务，按 [运维手册](operations.md) 正常停止。
2. 运行新安装包，按向导在原位置升级或修复。
3. 完成后重新打开应用，测试已有连接。

同一 Windows 用户在原位置升级后，继续使用正式版的连接配置、SAP 密码和 MCP 令牌。源码开发预览的数据独立保存。如果 API Key 只在开发预览中设置过，请在正式版的「模型设置」中重新录入。预览会话也保留在原环境。各环境的默认目录和端口见[本地数据说明](local-data.md#正式安装版与源码开发预览)。

同一 Windows 用户只安装一份应用，再次安装会使用原安装位置。需要更换位置时，先卸载再重新安装。

如果安装程序提示应用仍在运行，先正常退出后重试；不要强行删除锁文件。无法解决时查看 [故障排查](operations.md#8-常见故障)。

## 卸载

在 Windows“设置 → 应用”中找到 **SapLink**，或使用开始菜单中的卸载入口。

卸载移除应用及其快捷方式，保留连接配置、访问令牌、日志和已保存的 SAP 凭据。重新安装后可继续使用这些数据。如需清除个人数据，先查阅 [文件与备份说明](operations.md#7-文件权限与备份)，确认要保留的内容。
